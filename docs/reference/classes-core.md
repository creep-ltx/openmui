Classes: [Notify](#notify), [Family](#family), [Application](#application), [Window](#window), [Area](#area), [Rectangle](#rectangle), [Semaphore](#semaphore), [Dataspace](#dataspace), [Configdata](#configdata), [Menuitem](#menuitem), [Menu](#menu), [Menustrip](#menustrip), [Boopsi](#boopsi)

Generated by `tools/gen_reference.py` from the class sources and headers. Do not edit by hand; edit the autodoc in the class source, then regenerate. Part of the [reference](README.md).

**How to read the tables.** ISG is the flag set from the header (the MUI 3.8 one for MUI 3 attributes): i = may be given to `NewObject`, s = may be set, g = may be read. A trailing `*` means the header has no flags (MUI 4/5 names) and the letters were found by reading OpenMUI's own OM_NEW (i), OM_SET (s) and OM_GET (g) code; a blank means the attribute is handled elsewhere (a superclass or a module) or its flags are not visible in the class file. "Since" is the interface version the header gives (empty for MUI 4/5 names, which carry none). "not handled" means no built source file mentions the attribute (it is accepted and ignored). Meaning and default come from the autodoc block in the class source where one exists; an empty meaning means there is none, and the attribute behaves as in MUI's own documentation. The messages are the structures after `MethodID`.
